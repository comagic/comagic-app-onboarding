## HTTP-уведомления

<br>
<br>

<img src="HTTP-notification.svg" alt="" width="100%" height="260px"/>

<br>
<br>

Раздел позволяет автоматически передавать информацию о событиях в UIS во внешние системы: CRM, сервисы аналитики и другие приложения. При наступлении заданного события, например входящего звонка, нового сообщения в чате или смены статуса сотрудника, система отправляет HTTP-запрос на указанный URL.

<br>
<br>

### **Создание HTTP-уведомления**

<br>

**Основные параметры**

<br>

1. Задайте **название** HTTP-уведомления (до 100 символов).
2. Выберите **тип события**, при наступлении которого будет отправляться уведомление. События сгруппированы по продуктам: «Звонки», «Омни», «Аналитика рекламы». Также доступны общие события, например проставление и снятие тега, смена статуса сотрудника, выгрузка отчета.

<br>
<br>

**Условия**

<br>

В блоке «Условия» можно уточнить, **в каких случаях необходимо отправлять уведомление**. Например, настроить отправку уведомлений о смене статуса только определенных сотрудников. Доступные параметры, условия и значения зависят от выбранного типа события.

<br>

Для более гибкой настройки можно объединять несколько условий: добавлять альтернативное условие через «ИЛИ», когда достаточно выполнения одного из условий группы; добавлять группу условий через «И», когда для отправки уведомления должны выполняться требования каждой группы.

<br>
<br>

<Alert type="info">Если дополнительные **условия не заданы**, уведомление будет отправляться при каждом наступлении выбранного события. При **смене типа события** некоторые ранее заданные условия могут быть сброшены.</Alert>

<br>
<br>

**Настройка HTTP**

<br>

1. Выберите метод отправки HTTP-запроса:
- **GET** — данные передаются в параметрах URL.
- **POST** — данные передаются в теле HTTP-запроса.
2. В поле **«URL»** укажите адрес, на который будут отправляться уведомления.
3. При необходимости добавьте **HTTP-заголовки**. Для этого нажмите «Добавить Header» и заполните поля «Ключ» и «Значение».
4. В поле **«Текст уведомления»** сформируйте содержимое запроса.
В текст уведомления можно добавлять как собственный текст, так и **динамические параметры**. Для добавления параметра нажмите на иконку «+» под полем ввода и выберите необходимый параметр из списка. При отправке уведомления вместо параметров будут подставлены фактические данные о событии: имя сотрудника, время создания уведомления, идентификатор сотрудника и другие сведения.

<br>

Чтобы отменить изменения нажмите на иконку стрелочки под полем «Текст уведомления». Чтобы просмотреть пример сформированного HTTP-запроса, нажмите на иконку глаза.

<br>
<br>

<Alert type="warning">Уведомления отправляются с IP-адреса **195.211.122.249**. Если на стороне принимающей системы действуют ограничения по IP-адресам, необходимо разрешить получение запросов с этого адреса.</Alert>

<br>
<br>

### **Тестирование HTTP-уведомления**

<br>

Перед сохранением настроек **можно проверить отправку уведомления**. Для этого нажмите «Протестировать» в блоке «Настройка HTTP».
Если проверка прошла успешно, появится сообщение «Тестирование успешно». В случае ошибки проверьте параметры HTTP-запроса и доступность принимающей системы.
Нажмите «Сохранить». Созданное уведомление отобразится в общем списке HTTP-уведомлений.

<br>
<br>

### **Управление HTTP-уведомлениями**

<br>

В таблице отображаются все настроенные HTTP-уведомления, их названия, типы событий, методы отправки и URL.
Для поиска нужного уведомления воспользуйтесь поиском по названию или фильтрами по типу события, методу отправки и состоянию уведомления («Активные» и «Неактивные»).

<br>

В строке каждого уведомления доступны следующие действия:
- **Включение и отключение** — позволяет приостановить или возобновить отправку уведомлений без удаления настроек.
- **Редактирование** — позволяет изменить настройки уведомления.
- **Копирование** — позволяет создать новое уведомление на основе существующего.
- **Удаление** — позволяет удалить уведомление.

<br>
<br>

<Alert type="info">Пока **уведомление отключено**, события для него не собираются. **После включения** уведомления будут отправляться только по новым событиям. Если **два активных HTTP-уведомления имеют одинаковые настройки**, при наступлении соответствующего события запрос будет отправлен дважды.</Alert>
